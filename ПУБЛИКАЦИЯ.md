# Публикация на GitHub Pages

Сайт опубликован: https://moonlightovvl.github.io/booksore-lab/

Исходники: https://github.com/moonlightovvl/booksore-lab

Источник GitHub Pages: ветка `main`, папка `/` (корень репозитория). Главная страница доступна по HTTPS и возвращает HTTP 200.

## Что было сделано и почему

1. `git clone https://github.com/moonlightovvl/booksore-lab.git tmp/lab2/publish` — создана отдельная рабочая копия вашего репозитория. Так сохранён исходный коммит с README, а учебный проект остался на своём месте в `решения/2лаба`.
2. В корень рабочей копии скопировано содержимое готового проекта, включая `css`, `js` и `images`. Поэтому `index.html` находится сразу в корне сайта, а относительные ссылки ведут к нужным ресурсам.
3. `git add --all` — добавлены в индекс все подготовленные изменения. Индекс определяет, какие версии файлов войдут в коммит.
4. `git -c user.name=moonlightovvl -c user.email=353006314+moonlightovvl@users.noreply.github.com commit -m 'Complete CICADA laboratory work 2'` — сохранён коммит от вашего GitHub-аккаунта с приватным адресом GitHub noreply. Параметры `-c` действуют только для этой команды и не меняют глобальные настройки Git. Соавторы и строки `Co-authored-by` не добавлены.
5. `git push origin main` — коммит отправлен в ветку main вашего репозитория. Использован существующий вход Git на компьютере; новые пароли или токены не создавались и в проект не записывались.
6. Через официальный GitHub API проверено наличие Pages и включена публикация из `main` / `/`. Это программный эквивалент выбора **Settings → Pages → Deploy from a branch → main → / (root) → Save**. Существующее средство учётных данных Git передало авторизацию только в памяти процесса, без вывода в журнал или сохранения в файлах.
7. Проверен опубликованный HTTPS-адрес. Настройка Pages сама по себе не доказывает доступность сайта, поэтому отдельно запрошена настоящая страница магазина.
8. Итоговые пояснения сохранены и отправлены отдельным коммитом без соавтора, чтобы локальная папка и репозиторий содержали актуальную инструкцию.

## Как обновлять сайт дальше

Измените нужный файл в VS Code. Затем загрузите обновления в ту же ветку main через Git или веб-интерфейс GitHub. GitHub Pages автоматически опубликует изменения; новая настройка Pages не нужна. После публикации обновите страницу браузера.

Не загружайте папку `tmp/lab2/publish/.git` через веб-интерфейс: это служебная история Git. Для работы магазина нужны файлы из `решения/2лаба`.

Файл `.nojekyll` намеренно пуст и отключает обработку сайта Jekyll. Bootstrap хранится локально, сборка через npm не требуется.
